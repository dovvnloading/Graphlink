# Graphlink branding

## The app mark

`icon-h2-branch-chevron.svg` is **canonical**. A stem forking into two
directed branches — the app's core gesture, branching a conversation.

It is **generated, not hand-edited**. Both it and `assets/graphlink.ico` come
from one geometry definition in `tools/build_app_icon.py`:

```bash
python tools/build_app_icon.py
```

That rebuilds, from the same source:

| Output | Used by |
| --- | --- |
| `assets/branding/icon-h2-branch-chevron.svg` | canonical vector |
| `assets/graphlink.ico` | the desktop window (`graphlink_desktop.py`) |
| `web_ui/src/app/public/favicon.svg` | browser tab |
| `web_ui/src/app/public/favicon.ico` | browsers' automatic `/favicon.ico` request |

Editing the SVG by hand will be silently overwritten on the next build. Change
`STROKES` in the build script instead.

## Palette

| Role | Dark surfaces | Light surfaces |
| --- | --- | --- |
| Branch A | `#45c46f` | `#2fa85a` |
| Branch B | `#4a90e2` | `#2f74c4` |
| Stem / edge | `#7d8590` | `#8b939c` |

These are brightened relatives of the canvas node palette
(`GROUP_NAMED_COLORS` in `web_ui/src/app/canvas/GroupColorPicker.tsx`) — small
marks lose apparent saturation, so the icon runs a step hotter than the UI.

The shipped `.ico` uses the dark-surface values. They are mid-tone by design
and hold up on a light Windows title bar too, so one file covers both themes.

## Why the `.ico` has eight frames

The previous icon was a single 1024×1024 bitmap in an `.ico` container. Every
place Windows actually shows an app icon — title bar (16px), taskbar (24–32px),
Alt-Tab — was brute-force downscaling a poster, and the detail turned to mush.

The build script renders each size separately and tunes the margin per size, so
the small frames are drawn for their size rather than shrunk into it.

Two findings worth keeping, both learned the hard way while tuning:

- **Fattening strokes at small sizes backfires here.** The usual trick is to
  thicken lines so they land on whole pixels. The binding constraint for this
  mark is the chevron's *aperture* — the gap between its two arms — and a
  heavier stroke closes it, turning each chevron into a solid blob. Stroke is
  therefore constant across all sizes; only the margin varies.
- **The chevron angle has a narrow usable band.** Too tight and the aperture
  closes; past roughly 80° the arms splay and the pair stops reading as two
  arrows, becoming a flat zigzag. 8×11 arms at a 6-unit stroke (~72°) sits
  between those failure modes.

## The other concepts

The remaining `icon-*.svg` files are the explored alternatives, kept as internal
assets — usable for docs, plugin badges, splash art, social cards, or a future
rebrand. They are hand-authored and **not** regenerated by the build script.

| File | Concept |
| --- | --- |
| `icon-a-conversation-tree.svg` | three branching message bubbles |
| `icon-b-node-fork.svg` | one node branching into two |
| `icon-c-g-monogram.svg` | G letterform with a node terminal |
| `icon-d-bubble-fork.svg` | one bubble, thread forking into two nodes |
| `icon-e-linked-cards.svg` | two node cards joined by an edge |
| `icon-f-knockout-tile.svg` | solid tile, graph in negative space |
| `icon-g-node-handles.svg` | the canvas node card with its handles |
| `icon-h-branch-arrow.svg` | the original curved branch arrow |
| `icon-h1-branch-straight.svg` | straightened, filled arrowheads |
| `icon-h3-branch-asymmetric.svg` | one branch resolves to a node |
| `icon-h4-branch-tile.svg` | the branch knocked out of a tile |
| `icon-i-thread-branch.svg` | version-control style thread + branch |
| `icon-i1-thread-branch.svg` | refined, squared-off branch |
| `icon-j-split-bubble.svg` | one bubble cleaved in two |

`icon-f` and `icon-h4` are the tile-backed variants — the ones to reach for
when a mark needs to sit on an unpredictable background (installers, store
listings, favicons on coloured pages), since the tile carries its own contrast.
